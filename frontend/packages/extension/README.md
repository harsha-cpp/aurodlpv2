# AURO Chrome extension

Gmail MV3 content script that scans a draft before Gmail sends it, plus the
service worker that keeps the org's approved-recipient config cached locally.

## Build configuration

| Variable            | Default (dev)           | Default (production build) | Purpose |
| ------------------- | ----------------------- | -------------------------- | ------- |
| `VITE_BACKEND_URL`  | `http://localhost:8000` | `https://api.aurodlpv2.io` | Origin of the Auro backend. |

`VITE_BACKEND_URL` is read at **build time** in one place, `src/backend-url.ts`,
and feeds two things that must never disagree:

- `BACKEND_URL` in `src/config.ts`, used by the content script, the service
  worker and the warning modal;
- `host_permissions` in the generated manifest (`manifest.config.ts`). Chrome
  blocks any request to an origin the manifest does not list, so a hardcoded
  localhost permission in a packaged build silently disables every backend call
  and leaves the extension running on its weaker offline fallback.

```bash
# local development against a backend on localhost:8000
pnpm --filter @aurodlpv2/extension dev

# packaged build for a specific deployment
VITE_BACKEND_URL=https://auro-api.hospital.example pnpm --filter @aurodlpv2/extension build
```

Plain `http://` is rejected for anything but loopback, and a malformed value
fails the build rather than falling back to a default — a typo in CI must not
ship an extension pointed at the wrong host.

There is no `manifest.json`; it is generated by `manifest.config.ts` at build
time. Edit that file, not `dist/manifest.json`.

## Failing closed

The extension decides `allow` / `warn` / `block` from the org config the service
worker caches in `chrome.storage.local` under `aurodlp_config`.

When there is **no usable config** — no org code, the config fetch has never
succeeded, or the cached config lists no approved recipient — the extension does
not treat the message as approved. A draft containing detected patient data gets
a `warn` explaining that recipients could not be checked; ordinary mail is
unaffected. An org can opt back into the old permissive behaviour by returning
`fail_open: true` from `GET /api/v1/public/orgs/{org_code}/config`; absent means
`false`.

## Tests

```bash
pnpm --filter @aurodlpv2/extension test        # vitest (happy-dom)
pnpm --filter @aurodlpv2/extension test:e2e    # playwright, needs a built dist/
```

The send-path predicates (`src/content/send-paths.ts`), the policy decision
(`src/content/policy.ts`), sender identity (`src/content/identity.ts`) and the
backend URL resolution are pure modules precisely so they can be tested without
driving live Gmail.
