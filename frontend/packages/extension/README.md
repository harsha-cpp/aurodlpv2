# Auro Chrome extension

One MV3 extension with two independent content scripts and one service worker.

| Script | Matches | Runs | Decides |
|---|---|---|---|
| `src/content/index.ts` | `https://mail.google.com/*` | `document_idle`, top frame only | Server-side. Falls back to the local rule pack when the backend is unreachable. |
| `src/content/input-protection-entry.ts` | `http://*/*` and `https://*/*`, `exclude_matches` `https://mail.google.com/*` | `document_start`, all frames, `match_about_blank` | Locally and synchronously. No network call in the keystroke path. |

`src/background/index.ts` is the service worker. It caches the organization
config and relays web-input blocks to the backend.

There is no `manifest.json` in the tree. It is generated by `manifest.config.ts`
at build time. Edit that file, not `dist/manifest.json`.

## The Gmail path

Scans a draft before Gmail sends it, across every send path including scheduled
send. Uploads attachments, polls queued attachment scans, calls
`POST /api/v1/scan/finalize`, and renders the verdict as `allow`, `warn`,
`block`, `quarantine` or `escalate`.

### Failing closed

The extension decides from the org config the service worker caches in
`chrome.storage.local` under `blade_config`.

When there is no usable config, meaning no org code, or the config fetch has
never succeeded, or the cached config lists no approved recipient, the extension
does not treat the message as approved. A draft containing detected patient data
gets a `warn` explaining that recipients could not be checked; ordinary mail is
unaffected. An org can opt back into permissive behaviour by returning
`fail_open: true` from `GET /api/v1/public/orgs/{org_code}/config`; absent means
`false`.

## The universal web input path

`src/content/input-protection.ts` stops patient data being pasted or typed into
an editable field on any other site: ChatGPT, Gemini, a support form, a ticket
comment box.

It listens in the capture phase and blocks on `paste`, `beforeinput` (one check
per inserted keystroke, skipping IME composition), `drop`, `input` (an autofill
backstop that clears the field after the fact), `keydown` on Enter, `submit`, and
clicks on controls whose accessible name matches send, submit, ask, generate, run
or continue. A block is `preventDefault()` plus `stopImmediatePropagation()`.

Eligible fields are text-like `input` elements, `textarea` elements, and elements
that are `contenteditable` or carry `role="textbox"`. `TEXT_INPUT_TYPES` excludes
`password`, and the handler excludes it again by name. Disabled, read-only and
`aria-disabled` controls are skipped. `editableFromEvent` walks
`event.composedPath()`, so a field inside an open shadow root is still covered.

`MAX_INSPECTION_CHARS = 500_000`. A paste larger than that is blocked without
being inspected, so the guard fails closed rather than passing text it cannot
check in time.

### Standalone and contextual identifiers

`STANDALONE_ENTITY_TYPES` holds 17 types that block on their own: `IN_AADHAAR`,
`IN_PAN`, `IN_PASSPORT`, `IN_DRIVING_LICENSE`, `IN_VOTER_ID`, `ABHA_NUMBER`,
`ABHA_ADDRESS`, `MRN`, `PATIENT_VISIT_ID`, `LAB_ACCESSION`, `ICD10`,
`MEDICAL_LICENSE`, `INSURANCE_POLICY`, `BANK_ACCOUNT`, `IN_IFSC`, `IN_UPI`,
`IN_GSTIN`.

`CONTEXTUAL_ENTITY_TYPES` holds 4 that do not: `EMAIL_ADDRESS`, `IN_PHONE`,
`PERSON`, `DATE_OF_BIRTH`. `allowedHits()` keeps a contextual hit only when the
same inspected text also contains a standalone identifier, or matches the
`PATIENT_CONTEXT` keyword pattern.

The split is load-bearing. Blocking a bare email address made ordinary login and
signup forms unusable, and a name plus a phone number in a support ticket is not
patient data. The same name next to an MRN is.

### The notice

`createNotice()` renders into a **closed** shadow root inside a fixed-position
host, so the page cannot restyle it, query it, or read it back. It names the
entity types and never echoes the matched value. It removes itself after six
seconds, and only one is on screen at a time.

## Reporting a web block

A content script on an arbitrary site cannot POST to the backend: the request
carries the page's origin and CORS refuses it. Only two origins are in
`host_permissions`, `https://mail.google.com/*` and the backend, and the page is
neither.

So the content script sends a `WEB_BLOCK` runtime message (`src/web-block.ts`)
and the service worker makes the call, because it runs in the extension's own
context where `host_permissions` applies. The Gmail content script does not need
this hop, since Gmail's origin is itself in `host_permissions`.

The worker posts to `POST /api/v1/events` with `channel: "web"`, `site_host`
set to `location.hostname`, `action: "block"`, the entity types, confidences and
masked values, the risk score, the severity, the org code and a fresh
`client_event_id`. It aborts after `WEB_BLOCK_TIMEOUT_MS = 5_000`.

Three limits:

- `WEB_BLOCK_DEDUPE_MS = 60_000`. Repeats of the same
  `site_host | reason | sorted entity types` key inside 60 seconds are dropped.
  The map is in worker memory, so it resets when Chrome suspends the worker.
- No org code in `chrome.storage.local` means no report at all.
- Reporting is best effort. It runs after the block has already happened, inside
  a `try/catch`, and a failed report can never turn a block into an allow.

The raw typed or pasted text, the page URL, the page title and the field name are
never sent. See [`../../../docs/privacy.md`](../../../docs/privacy.md).

## Build configuration

| Variable | Default (dev) | Default (production build) | Purpose |
|---|---|---|---|
| `VITE_BACKEND_URL` | `http://localhost:8000` | `https://api.aurodlpv2.io` | Origin of the Auro backend. |

`VITE_BACKEND_URL` is read at build time in one place, `src/backend-url.ts`, and
feeds two things that must never disagree:

- `BACKEND_URL` in `src/config.ts`, used by the content script, the service
  worker and the warning modal;
- `host_permissions` in the generated manifest. Chrome blocks any request to an
  origin the manifest does not list, so a hardcoded localhost permission in a
  packaged build silently disables every backend call and leaves the extension
  running on its weaker offline fallback.

```bash
# local development against a backend on localhost:8000
pnpm --filter @bladedlp/extension dev

# packaged build for a specific deployment
VITE_BACKEND_URL=https://blade-api.hospital.example pnpm --filter @bladedlp/extension build
```

Plain `http://` is rejected for anything but loopback, and a malformed value
fails the build rather than falling back to a default. A typo in CI must not ship
an extension pointed at the wrong host.

## Tests

```bash
pnpm --filter @bladedlp/extension test        # vitest, happy-dom
pnpm --filter @bladedlp/extension test:e2e    # playwright, needs a built dist/
```

The send-path predicates (`src/content/send-paths.ts`), the policy decision
(`src/content/policy.ts`), sender identity (`src/content/identity.ts`), the
web-input guard (`src/content/input-protection.ts`) and the backend URL
resolution are pure modules precisely so they can be tested without driving live
Gmail. `installInputProtection()` returns a disposer, which is what lets the
guard's tests tear it down between cases.

Both suites drive a synthetic DOM. Nothing here exercises a real Gmail session or
a real ChatGPT page.
